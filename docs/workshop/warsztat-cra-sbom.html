Po co to robimy

SBOM (Software Bill of Materials) to spis treści oprogramowania: każda biblioteka, jej wersja, licencja i identyfikator purl. Cyber Resilience Act (CRA) wymaga, żeby producent produktu z elementami cyfrowymi znał skład i umiał powiązać go ze znanymi podatnościami.

Inwentarz
Co weszło do binarki i backendu — Rust, Python, npm, modele, ffmpeg.
Podatności
CVE + ocena CVSS. Sam plik licencyjny nie zawiera CVE, dopóki go nie przeskanujesz.
Priorytet
CVSS mówi „jak ciężko”, EPSS i CISA KEV / EUVD mówią „czy ktoś to już wykorzystuje”.

Najczęstszy błąd na sali: otwieracie gotowy *.cdx.json w Sunshine i widzicie 0 vulnerabilities. To nie znaczy, że produkt jest czysty. Znaczy, że ten SBOM jest inwentarzem (licencje, komponenty), a nie wynikiem skanera. CVE trzeba dodać drugim krokiem.

Pipeline, który rysujesz na tablicy

1. ŹródłoRepozytorium: Cargo.lock, package-lock.json, requirements.txt / venv.
2. GeneratorTrivy, Snyk albo Syft czyta lockfile’e i zapisuje CycloneDX JSON.
3. SkanerTen sam Trivy, Snyk albo Grype dopisuje CVE, wektor i score CVSS.
4. WidokSunshine (albo Snyk UI) robi HTML z tabelą i wykresem.

Format: CycloneDX 1.5 JSON (*.cdx.json). SPDX jest równoważny prawnie; tu zostajemy przy CycloneDX, bo tak wyglądają pliki rAIdio.bot.

Krok 2 — SBOM bezpośrednio ze źródła

Wejdź do katalogu aplikacji (tam, gdzie jest Cargo.toml / package.json / Python). Nie skanujemy tu repozytorium sbom/ — to archiwum gotowych BOM-ów. Skanujemy kod produktu.

Wariant A — Trivy (pokaz główny)

PowerShellcd C:\sciezka\do\zrodla-aplikacji

# Tylko inwentarz (komponenty + licencje, bez CVE)
trivy fs --format cyclonedx --output sbom.cdx.json .

# Inwentarz + podatności w jednym pliku (to chcemy na projektorze)
trivy fs --scanners vuln,license --format cyclonedx --output sbom-vuln.cdx.json .

Trivy czyta lockfile’e. Sam requirements.txt bez zamrożonych wersji daje gorszy wynik — CRA lubi pinned versions.

Wariant B — Snyk

PowerShellcd C:\sciezka\do\zrodla-aplikacji
snyk sbom --format=cyclonedx1.5+json -o sbom.snyk.cdx.json
Get-Item sbom.snyk.cdx.json

Snyk wykrywa ekosystem sam (npm, pip, Maven, NuGet, Cargo przez manifest). Dla monorepo wskaż plik:

PowerShellsnyk sbom --format=cyclonedx1.5+json --file=package.json -o frontend.cdx.json
snyk sbom --format=cyclonedx1.5+json --file=src-tauri/Cargo.toml -o rust.cdx.json

Wariant C — Syft

PowerShellsyft dir:. -o cyclonedx-json=sbom.syft.cdx.json

Co sprawdzić w JSON-ie

PowerShellpython -c "import json; d=json.load(open('sbom-vuln.cdx.json',encoding='utf-8')); print('spec', d.get('specVersion')); print('components', len(d.get('components') or [])); print('vulnerabilities', len(d.get('vulnerabilities') or []))"
  • bomFormat = CycloneDX, specVersion 1.4–1.6.
  • Każdy komponent: name, version, purl (np. pkg:pypi/torch@2.10.0).
  • Po skanie vuln: tablica vulnerabilities[] z id typu CVE-… i ratings[].score.

Trivy i Snyk — kliknij, nie kopiuj

Te przyciski uruchamiają skaner na tej maszynie (nie wklejają komendy). Strona file:// sama nie startuje procesów — lokalny helper na 127.0.0.1 to robi. Na pendrive bez Pythona: dwuklik run-trivy.cmd / run-snyk.cmd.

Sprawdzam, czy lokalny runner nasłuchuje na 127.0.0.1…

Pobierz run-trivy.cmd Pobierz run-trivy.ps1 Pobierz run-snyk.cmd Pobierz run-snyk.ps1 Pobierz start-scan-server.cmd

Gdy przycisk mówi, że runner śpi: w PowerShell, w katalogu repozytorium:

PowerShellpython tools\workshop_scan_server.py
# potem odśwież tę stronę albo otwórz http://127.0.0.1:18767/warsztat-cra-sbom.html

Snyk bez snyk auth nie skanuje — przycisk i skrypt zapiszą wtedy plik z komunikatem snyk auth required. Trivy nie wymaga konta.

CVE i „korekta” CVSS

Jeśli jest już czysty SBOM (jak releases/v0.1.36/rAIdio.bot-v0.1.36.cdx.json — 1196 komponentów, 0 CVE), skanuje się plik, nie źródło drugi raz. Na sali: najpierw przyciski Trivy / Snyk, poniżej te same komendy.

Trivy czyta SBOM

PowerShelltrivy sbom --format cyclonedx --output sbom-vuln.cdx.json .\releases\v0.1.36\rAIdio.bot-v0.1.36.cdx.json
trivy sbom --severity HIGH,CRITICAL .\releases\v0.1.36\rAIdio.bot-v0.1.36.cdx.json

Snyk czyta SBOM

PowerShellsnyk sbom test --file=.\releases\v0.1.36\rAIdio.bot-v0.1.36.cdx.json

Grype czyta SBOM i z powrotem zapisuje CycloneDX

PowerShellgrype sbom:.\releases\v0.1.36\rAIdio.bot-v0.1.36.cdx.json -o cyclonedx-json=sbom-vuln.cdx.json

OSV-Scanner (bez konta)

PowerShellosv-scanner scan --sbom=.\releases\v0.1.36\rAIdio.bot-v0.1.36.cdx.json --format=cyclonedx-1.5 --output=sbom-osv.cdx.json

Projektor bez skanowania na sali: w katalogu viewer/ leżą już wyniki skanu (gdy skrypt je zapisze) — tabela CVE offline, Sunshine rAIdio.bot-v0.1.36-osv.html, indeksy results/vuln/osv-index.html i results/vuln/grype-index.html.

Dlaczego liczby się nie zgadzają między narzędziami? To jest slajd „korekta CVSS”, nie błąd skanera.

  • NVD nadaje CVSS 3.1 / 4.0 z opóźnieniem; czasem score jest pusty.
  • GitHub Advisory / Snyk / OSV często mają score wcześniej, czasem inny.
  • CVSS = jak bardzo boli technicznie (0–10). Nie mówi, czy ktoś to exploitował.
  • EPSS = prawdopodobieństwo wykorzystania w 30 dni.
  • CISA KEV i ENISA EUVD / EU KEV = potwierdzone wykorzystanie. Na CRA to jest ważniejsze niż sam score 9.8.

Sunshine z flagą -e dociąga EPSS i CISA KEV do identyfikatorów CVE-…. Publiczne bazy:

  • nvd.nist.gov — CVSS „oficjalny USA”
  • cve.org — rekord CVE
  • osv.dev — baza Google, bez logowania
  • euvd.enisa.europa.eu — baza UE, kontekst CRA
  • CISA KEV
  • first.org/epss — prawdopodobieństwo exploita

Krok 4 — raport HTML na projektor

Najszybciej: Sunshine w przeglądarce (zero instalacji)

  1. Otwórz cyclonedx.github.io/Sunshine.
  2. Zaznacz Enrich data with EPSS and CISA KEV.
  3. Wgraj sbom-vuln.cdx.json (plik ze skanerem, nie surowy inwentarz).
  4. Plik nie wychodzi z przeglądarki — nadaje się do sali.

Albo HTML na dysk (offline na konferencji)

PowerShellgit clone --depth 1 https://github.com/CycloneDX/Sunshine.git $env:TEMP\Sunshine
pip install requests
python $env:TEMP\Sunshine\sunshine.py -i sbom-vuln.cdx.json -o raport.html -e -nl
start raport.html

W raporcie widać: liczbę komponentów, liczbę CVE, kolumnę CVSS, kolumnę EPSS, czy coś wpadło do CISA KEV. Szukanie po nazwie pakietu działa (np. torch).

Gotowy inwentarz rAIdio.bot v0.1.36 bez CVE: viewer/rAIdio.bot-v0.1.36.html. Raport po skanie (gdy skrypt go zapisze): viewer/rAIdio.bot-v0.1.36-osv.html i tabela CVE offline. Żeby na Sunshine w chmurze pojawiły się czerwone wiersze, wgraj plik ze skanerem z kroku 3.
